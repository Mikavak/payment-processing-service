## Исправленные проблемы

* Настроен импорт `app` при запуске pytest.
* Некорректные сообщения валидируются внутри обработчика с ручным ACK, поэтому
  ошибки декодирования также отправляются в DLQ.
* Устранена ошибка кодирования `x-delivery-limit=-1` в pamqp 3.3. Используется
  отдельный транспортный лимит 1000; счётчик бизнес-попыток по-прежнему равен 3.
* Тест redelivery использует подписку: RabbitMQ не разрешает `basic.get` для
  quorum-очереди с single-active-consumer.
* Удалены значения рабочих паролей по умолчанию; `.env` генерируется локально,
  исключён из Git/Docker-контекста, права доступа `0600`.
* Все замечания Ruff устранены.

## Оставшиеся ограничения

Неисправленных падений тестов или ошибок запуска после проверки нет.

* Шлюз является эмуляцией по ТЗ; реального списания денег нет.
* Доставка webhook — at-least-once. При сбое после HTTP-успеха до commit возможно
  повторное уведомление; получатель должен дедуплицировать стабильный `event_id`.
* Для production нужны egress/allowlist webhook, TLS/подпись уведомлений,
  мониторинг, очистка опубликованного outbox и процедура разбора DLQ.
* Тесты инъецируют сбои в конкретные окна транзакций и проверяют настоящий брокер,
  но не моделируют потерю диска или сетевое разделение RabbitMQ-кластера.
